# Model Latency Insights (Preview)

`azure.ai.latency` assesses deployed Azure OpenAI model workloads. It combines
deployment metadata, Azure Monitor metrics, request-level diagnostic logs,
current-offer targets, and exact workload benchmark cohorts to explain observed
latency and recommend the next test.

This extension is intentionally separate from `azure.ai.models`, which manages
custom-model registry operations. It is not included in the
`microsoft.foundry` extension pack.

## Commands

| Command | Description |
| --- | --- |
| `azd ai latency assess` | Assess a deployed model workload with live Azure data. |
| `azd ai latency demo` | Explore deterministic decision paths without Azure access. |
| `azd ai latency version` | Display the extension version. |

### Assess a deployment

Identify the deployment with its complete ARM resource ID:

```powershell
azd ai latency assess `
  --deployment-id "/subscriptions/<subscription>/resourceGroups/<resource-group>/providers/Microsoft.CognitiveServices/accounts/<account>/deployments/<deployment>"
```

Alternatively, provide the four resource components:

```powershell
azd ai latency assess `
  --subscription <subscription-id> `
  --resource-group <resource-group> `
  --account-name <account> `
  --deployment-name <deployment>
```

When values are omitted, interactive runs prompt for them. In automation, use
`--no-prompt`; the command fails with a validation error if any required value
is unresolved. An explicitly supplied `--deployment-id` cannot be combined
with the four component flags.

The default window is the last 24 hours. Use another relative window or an
exact UTC range:

```powershell
azd ai latency assess --deployment-id <resource-id> --last 7d

azd ai latency assess --deployment-id <resource-id> `
  --start-time 2026-09-01T08:00:00Z `
  --end-time 2026-09-02T08:00:00Z
```

Request offer-fit guidance when the current target is met:

```powershell
azd ai latency assess --deployment-id <resource-id> `
  --latency-goal lower-or-predictable
```

Use JSON for automation and choose the report path independently:

```powershell
azd ai latency assess --deployment-id <resource-id> `
  --output json `
  --report artifacts/latency-report.html
```

`--report ""` disables HTML generation. `--open` opens the generated report
and is rejected when the report path is empty. Progress and report-path
messages are written to stderr so JSON on stdout remains machine-readable.
Use `--no-progress` to suppress assessment progress.

### Explore demo scenarios

List the deterministic scenarios:

```powershell
azd ai latency demo --list-scenarios
```

Run one scenario:

```powershell
azd ai latency demo --scenario workload-explained
```

Available scenarios:

| Scenario | Decision path |
| --- | --- |
| `within-target` | Current-offer target met; benchmark not required. |
| `lower-latency-needed` | Target met; PTU-M is an illustrative eligible option. |
| `workload-explained` | Target exceeded; exact benchmark explains the workload gap. |
| `unexplained-gap` | Target and benchmark exceeded; support evidence is generated. |
| `no-benchmark-coverage` | Target exceeded; strict benchmark coverage is unavailable. |
| `logs-unavailable` | Aggregate metrics exist without request-level percentiles. |

Demo output is clearly labeled `Illustrative sample data`. The default HTML
report contains the four primary decision paths and a scenario selector, while
terminal or JSON output contains the selected scenario.

## Assessment contract

The public JSON result uses `schema_version: "1.0"` and contains:

- the resolved UTC time range and deployment profile;
- token, request-rate, and latency distributions;
- the current-offer target assessment;
- an exact-bucket LLM-Runner benchmark comparison when required;
- evidence-backed workload recommendations;
- live or illustrative offer eligibility;
- a customer-safe evidence package for unexplained target violations; and
- per-source data availability.

The v1 product rules, target catalog, benchmark cohorts, and their schemas are
bundled under `internal/contracts/`. Benchmark matching never substitutes an
adjacent token bucket.

Reports never include raw prompts, credentials, secrets, internal endpoints,
or Log Analytics query text. The HTML report has no external scripts or style
assets and escapes all dynamic content. Golden tests compare the Go renderer
byte-for-byte with reports generated by the standalone reference CLI.

## Azure access and data availability

Run `azd auth login` before a live assessment. The selected subscription's
user-access tenant is used for credentials, including multi-tenant and guest
accounts.

The signed-in identity needs:

- read access to the Cognitive Services account and model deployment;
- access to Azure Monitor metrics for the account;
- permission to query resource-scoped Log Analytics data; and
- model, capacity, and quota read access for live offer eligibility.

The extension queries these platform metrics at one-minute granularity:

- `AzureOpenAIRequests`
- `ProcessedPromptTokens`
- `GeneratedTokens`
- `AzureOpenAINormalizedTTFTInMS`
- `AzureOpenAINormalizedTBTInMS`
- `AzureOpenAITTLTInMS`

Request-level distributions use `AzureOpenAIRequestUsage` and
`RequestResponse`, with an `AzureDiagnostics` compatibility fallback.
Diagnostic logs are not retroactive. A metrics or logs query failure produces
an explicit partial or unavailable data source instead of discarding usable
deployment evidence.

## Build and validate

From this directory:

```powershell
azd x build
azd ai latency version
azd ai latency demo --scenario unexplained-gap --report artifacts/demo.html
go test ./...
```

The first-party release pipeline publishes cross-platform binaries after the
extension is admitted to the appropriate extension registry.
